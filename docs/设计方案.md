# 足彩「14 场胜负 / 任选九」预测模型 — 设计方案

- 版本：v1.0
- 日期：2026-09-18
- 状态：设计稿（未实现）

---

## 1. 项目背景与目标

### 1.1 目标

对中国体育彩票「胜负彩（14 场）」「任选九场（任九）」：

1. 每期给出 **14 场比赛的胜/平/负概率**（三路模型融合 + 校准）；
2. 在 **每期、每个玩法不超过设定预算** 内构造**容错型投注方案**（复式覆盖，允许错 1 场仍有奖可中）。预算口径：14 场与任九**各自独立**，默认各 64 元（= 32 注，2 元/注），**金额为配置项可自行设定**；
3. 赛后自动对奖、累计长期战绩（投入 / 中奖 / ROI）。

### 1.2 数据范围

- 历史：近五个赛季（2021/22 – 2025/26）比赛结果 + 多家博彩公司欧赔；
- 当期：体彩官方接口的当期对阵、赔率与开奖结果。

### 1.3 交付形态

本机运行的 Web 应用：FastAPI + SQLite + 单页前端（ECharts）。四个页面：本期预测、推荐方案、历史战绩、回测报告。抓数 / 训练 / 预测另有命令行入口。

### 1.4 非目标（明确不做）

- 自动投注、代购、任何形式的资金操作；
- 14 场与任九之外的玩法（四场进球、六场半全场等）；
- 爬取非公开数据、绕过风控。
- **不承诺盈利**（见 1.5）。

### 1.5 预期管理（先立规矩）

- 足球胜平负市场效率很高，**没有模型能保证盈利**；彩票本身含抽水，长期期望为负是常态。
- 本项目的价值定位：**同等投入下提高覆盖效率与决策透明度**，效果只认回测数据。
- 验收底线（越不过即视为失败）：
  - 概率层：融合模型 logloss / Brier **不劣于**纯市场基线；
  - 方案层：回测 ROI 与命中率**对照"纯赔率方案"** 持平或更优。
- 达不到底线时的既定动作：**以市场概率为主**（模型仅做增量修正），而不是硬堆模型。

## 3. 数据层设计

### 3.1 数据源

| 数据 | 来源 | 状态 |
|---|---|---|
| 历史比赛结果 + 欧赔 + 技术统计 | `football-data.co.uk /mmz4281/{赛季}/{联赛}.csv`（免费 CSV） | 已验证直连可下载（示例：英超 2024/25 赛季 381 行，含比分、半场比分、射门/角球/红黄牌、十多家公司欧赔） |
| 当期对阵 / 赔率 / 开奖结果 | 中国体彩网 `webapi.sporttery.cn` | 已验证可达（HTTP 200）；**具体接口与参数需实现阶段实测确定**（含历史开奖回溯接口） |
| 兜底 | 手工录入（对阵阵营、赔率、开奖） | 接口不可用或字段缺失时使用 |

> 500 彩票等站点有反爬（实测 567），不作为数据源。

### 3.2 联赛覆盖

优先覆盖足彩常客且 football-data 有稳定数据的联赛：

- 英超 / 英冠（E0/E1）、德甲（D1）、意甲（I1）、西甲（SP1）、法甲（F1）、荷甲（N1）、葡超（P1）、苏超（SC0）等；
- 日职、巴甲、北欧等无稳定免费历史的联赛：**仅靠市场赔率路提供概率**（见 4.4 降级规则），模型路缺失不阻塞出方案。

### 3.3 SQLite 表结构（要点）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `leagues` | code, name_cn, name_en | E0、D1… |
| `teams` | id, name_en, name_cn | 英文名来自历史数据 |
| `team_alias` | name_cn, team_id, confirmed | 足彩中文队名 → teams 映射 |
| `matches` | league, season, date, home/away_team_id, goals, result, odds_json, shots_json | 历史比赛；odds_json 存多家公司欧赔 |
| `periods` | period_no, draw_date, sale_end, status | 一期一行；14 场与任九共用期号，玩法归 plans.game_type |
| `period_matches` | period_id, seq(1-14), home/away 中文名, match_id(FK可空), 官方赔率 | 当期对阵；match_id 为空表示未映射 |
| `predictions` | period_match_id, market/dc/gbdt/fused 概率, model_version | 每期预测留档，便于复盘 |
| `plans` / `plan_legs` | period_id, game_type, budget, notes_count, objective, 每场选择集 | 推荐方案 |
| `draw_results` | period_id(PK), results_json(14 场结果), prizes_json(各奖级单注奖金) | 开奖 |
| `winnings` | period_id, plan_id, 奖级, 注数, 单注奖金, 合计 | 对奖结果 |
| `model_versions` | type, params_json, trained_at, metrics_json | 模型版本与指标 |

### 3.4 队名映射

1. 初始化：整理一张常见足彩球队的中英对照表（约 200–300 支）作为种子；
2. 每期新增对阵自动模糊匹配（编辑距离 + 别名规则）；
3. 剩下未确认的在 Web 页面人工点选确认，落库 `team_alias`（confirmed=1）；
4. 回测中发现"某队映射后的历史战绩异常"时告警复查。

### 3.5 数据新鲜度与降级

- 抓取失败：重试（指数退避）+ 使用缓存；页面显示"数据截至时间"。
- 单场缺赔率：该场只用模型路（DC / GBDT）。
- 单场三路信号全缺（连赔率都没有）：按均匀先验（1/3, 1/3, 1/3）兜底出概率，页面高亮提醒并允许人工覆盖；方案引擎照常工作。
- 未映射球队：按"缺历史数据"处理（Dixon-Coles 用联赛均值先验，GBDT 特征置缺失值）。

## 4. 模型层

三路信号各自独立可回测，最后融合校准。

### 4.1 市场路（基线，最强单路）

- 输入：多家公司欧赔（football-data 自带 B365/BW/PS/WH/Avg/Max 等）。
- 去水：**Shin 方法**为主（对足球 1X2 比简单归一化更稳），简单归一化法（`p_i/Σp`）作对照。
- 口径试验：均价 vs 最高价；用回测 logloss 选最优。
- 输出：每场胜/平/负三概率。

### 4.2 统计路：Dixon-Coles

- 基础：双泊松模型，`log λ主 = α主 + β客 + γ(主场优势)`，客队对称；
- 修正一：低比分相关性——对 0:0 / 1:0 / 0:1 / 1:1 四个格点引入参数 ρ；
- 修正二：**时间衰减**——每场比赛按 `ξ^Δt` 加权（近期权重大，半衰期可调，初值约半年，回测选优）；
- 拟合：按联赛单独做最大似然（scipy，带攻防参数和为零的约束）；
- 输出：进球数概率矩阵 → 求和得胜/平/负概率。
- 参数少、可解释、对五年数据量刚好；新升班马用联赛均值先验。

### 4.3 ML 路：梯度提升树（LightGBM）

- 任务：三分类（胜/平/负），multi-class logloss；库首选 LightGBM，Python 3.14 装不上则用 sklearn `HistGradientBoostingClassifier` 兜底。
- 特征（全部赛前可得）：

| 类别 | 特征 |
|---|---|
| 近期状态 | 近 5 / 10 场积分、进失球、射门/射正/被射门（近似 xG） |
| 分场地状态 | 主队近 N 个主场、客队近 N 个客场同套指标 |
| 强度 | Elo 评分（5 年滚动，含主场加成与赛季回归）、Elo 差 |
| 体能 | 双方休息天数差 |
| 联赛 | 联赛场均进球、主胜率、平局率 |
| 赛季阶段 | 第几轮 / 总轮数（收官期动机差异） |
| 赔率（仅分析版） | 去水市场概率。仅用于独立对比研究；**进入融合的 GBDT 一律用不含赔率的特征训练**（赔率信息已由 4.1 市场路承载，避免重复计分） |

- 防泄漏铁律：所有滚动特征按比赛时间严格后移（只用赛前信息）；训练/验证按时间切分。
- 训练节奏：每月（或每 4 期）重训一次，早停用最近一个赛季做验证。

### 4.4 融合与校准

- 融合按**信号可用性分档，每档独立拟合**（训练时按同样的可用性模式切分样本）：
  - 三路齐全 → 9 维逻辑回归 stacking（对数概率输入 → 3 类输出）；
  - 缺一路 → 剩余两路的对数概率加权（权重在"该组合可用"的样本上拟合）；
  - 仅市场路（日职、巴甲等无稳定历史联赛的**常态**）→ 直接使用市场去水概率，不叠加模型。
- 关键要求：拟合融合权重用的各路预测必须是 **out-of-fold**（每路在训练段内部做滚动预测），否则权重会被高估。
- 校准：**温度缩放**为主（多分类原生支持，按联赛或全局，回测选优）；isotonic 用于三分类需按类 OvR 再归一化，复杂度高，仅作备选。校准保证"说 60% 就是 60%"，直接影响方案构造的正确性。
- 重拟合节奏：每期用滚动窗口重拟合融合与校准参数（秒级）。

### 4.5 模型留档

每次训练写入 `model_versions`（参数、时间、回测指标），每期预测留档，保证任何一期的结果都能复盘。

## 5. 回测协议（成败关键）

- **Walk-forward**：以 2021/22–2024/25 为训练段，2025/26（或最近一个完整周期）逐期滚动预测；每期只使用当期之前的数据。
- 概率层指标：logloss、Brier；**核心对照是纯市场基线**——融合打不过基线即触发 1.5 的既定动作。
- 方案层指标：每期按设定预算（默认 64 元/玩法）跑方案引擎，统计
  - 14 场：一等奖中奖次数、二等奖中奖次数；
  - 任九：中奖次数；
  - 投入 / 奖金 / ROI / 中奖期数分布；
  - 对照"纯赔率方案"（同预算、同优化器、只用市场概率）。
- 防过拟合纪律：所有超参只在训练段调，指标只报未见段；参数敏感性（半衰期、融合权重）出具表格而不是只报最优点。
- **前置依赖**：方案层回测需要历史各期的真实 14 场对阵与开奖（见 P1 验收）；若历史期次对阵无法获取，退化为"比赛级回测"（按单场比赛模拟方案构造与奖级），并在报告中标注口径差异。

## 6. 方案引擎（预算内容错，默认 64 元/玩法）

### 6.1 数学定义

- 每场 i 选择集合 `S_i`（1/2/3 个结果），注数 `注 = Π|S_i| ≤ 预算/2`（2 元/注；预算为配置项，默认 64 元 → 上限 32 注）；
- 覆盖概率 `c_i = Σ_{s∈S_i} p_is`；
- 一等奖（14 场全对）：`P1 = Π c_i`；
- 二等奖（对 13 场）：`P2 = Σ_i (1−c_i)·Π_{j≠i} c_j`；
- 中奖概率（任一一/二等奖）：`P1 + P2`——全对时同样持有对 13 场的注，口径必须合并；任九只有全对一档：`P = Π_{i∈9} c_i`。

### 6.2 算法：枚举 size 向量（精确最优）

- 关键引理：固定各场选择数 `m_i` 后，每场取**概率最高的 m_i 个结果**，使每个 `c_i` 同时达到最大；本项目使用的两个目标 `P1` 与 `P1 + P2` 均对每个 `c_i` 单调不减（`∂(P1+P2)/∂c_k = Σ_{i≠k}(1−c_i)·Π_{j≠i,k}c_j ≥ 0`），故该取值即最优取值。**注意**：单独最大化 `P2` 不满足单调性（近全对时会倾向少选），"保二等"必须写作 `max(P1 + P2)`；
- 于是只需枚举"每场选几个"的 **size 向量** `(m_1…m_14)`，`m_i ∈ {1,2,3}`，约束 `Πm_i ≤ 预算/2`（默认预算下约 1 万个可行向量），逐个计算 P1/P2 取最大即可：**毫秒级、精确、无近似**；
- 任九：枚举"9 场子集 × size 向量"（2002 个子集 × 约 1600 个向量 ≈ 300 万组合，numpy 向量化秒级）；如嫌慢可用分组背包 DP（`dp[场次][已选场数][注数]`）求同一最优解，两者互为交叉验证。

### 6.3 目标切换

- **冲一等奖**：目标 `max P1`；
- **保二等奖**：目标 `max (P1 + P2)`，与冲一等共用同一套枚举，只是取值口径不同；
- **任九**：目标 `max Π c_i`（任九只有全对一档），枚举或 DP 均可。

### 6.4 输出

- 每场的选择（3/1/0 中选哪几个）、注数、金额、各奖级理论概率；
- **按注展开的单式清单**（32 行号码，可打印照着打）；
- 解释信息：每场"该选几个"的原因（融合概率的分散度）。

## 8. 实施步骤（阶段 + 验收标准）

| 阶段 | 任务 | 验收标准 |
|---|---|---|
| P0 环境 | venv + requirements（httpx、pandas、numpy、scipy、scikit-learn、lightgbm、fastapi、uvicorn、pytest）；确认 3.14 下全部可安装 | 全部 import 通过；LightGBM 不可用则切 sklearn 兜底 |
| P1 数据管道 | football-data 采集器（5 赛季 × 联赛清单）→ SQLite；体彩 webapi 参数实测（当期对阵/赔率/开奖）；**历史期次对阵**（接口/页面解析，兜底手工录入）；队名映射表 | 近 5 年 ≥8 个联赛入库且去重正确；当期对阵可入库并完成映射；**至少最近 1 个完整赛季的历史期次对阵 + 开奖可按期查询**（方案层回测的前置依赖） |
| P2 基线回测 | Shin 去水 + walk-forward 回测框架 | 产出市场基线 logloss/Brier 数字（后续所有对照的锚点） |
| P3 统计路 | Dixon-Coles 拟合 + 回测 | logloss 与基线差距在可接受范围（预期略逊，供融合用） |
| P4 ML 路 | 特征工程 + GBDT 训练 + 回测 | 无特征泄漏（单测验证）；指标记录在案 |
| P5 融合校准 | OOF 分档融合（stacking/加权）+ 温度缩放 + 回测 | **融合 logloss ≤ min(单路) 且不劣于市场基线**（否则启用市场为主的降级策略） |
| P6 方案引擎 | size 向量枚举 + 单测 + 方案层回测 | 小规模（≤6 场）与暴力穷举对拍一致；任九"枚举"与"DP"两法结果一致；回测输出每期方案与中奖统计；对照纯赔率方案 |
| P7 Web | 四页 + CLI | 每期端到端流程可在页面完成；方案可打印照打 |
| P8 对奖闭环 | 开奖采集 → 自动对奖 → 战绩累计 | 用最近 3 期历史数据回放，对奖结果与体彩官网一致 |

## 附录：关键公式

**Shin 去水**（3 结果，赔率 o_i，原始概率 p_i = 1/o_i，B = Σp_i）：

```
π_i = (√(z² + 4(1−z)·p_i²/B) − z) / (2(1−z))，解 z 使 Σπ_i = 1
```

**Dixon-Coles 低比分修正**（x = 主队进球，y = 客队进球）：

```
τ(0,0)=1−λμρ   τ(1,0)=1+μρ   τ(0,1)=1+λρ   τ(1,1)=1−ρ   τ(其他)=1
P(x,y) = τ(x,y) · Poisson(x;λ) · Poisson(y;μ)
```

**时间衰减**：比赛权重 `w = ξ^(距今天数)`，ξ 由回测选取（初值对应半衰期约 180 天）。

**覆盖概率与奖级**（见 6.1）。

**复式对奖注数**（开奖结果为单值；`v_i = 1` 若真实结果 ∈ `S_i`，否则 0；`A = {i : v_i = 1}`）：

- 一等奖注数 = `Π v_i`（0 或 1）；
- 二等奖注数：`|A| = 14` 时为 `Σ_i (|S_i| − 1)`；`|A| = 13`（缺场为 k）时为 `|S_k|`；`|A| ≤ 12` 时为 0；
- 任九只有全对一档：9 场全覆盖才有 1 注中奖，否则为 0；
- 奖金 = 对应奖级单注奖金 × 注数（单注奖金来自开奖公告）。
